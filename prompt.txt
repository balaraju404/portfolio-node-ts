## API

Create a sample `Users` module demonstrating the complete architecture.

Implement:

### POST /api/v1/users

Create a user.

Validate:

* name
* email
* password

Do not store passwords as plain text.

### GET /api/v1/users

Return a paginated list of users.

Support:

* page
* limit
* sorting
* basic filtering

### GET /api/v1/users/:id

Return a user by MongoDB ObjectId.

### PATCH /api/v1/users/:id

Update a user.

### DELETE /api/v1/users/:id

Delete a user.

Use appropriate HTTP status codes and consistent API responses.

## Important Requirements

* Use the latest stable package versions.
* Verify package compatibility before generating `package.json`.
* Do not use deprecated APIs.
* Do not use CommonJS unless there is a specific compatibility reason.
* Do not use `any` unless absolutely unavoidable.
* Do not use `@types/express` or other type packages if they are unnecessary because the package already provides its own types.
* Do not introduce unnecessary abstractions.
* Keep the code readable and maintainable.
* Follow SOLID principles where they provide real value.
* Use dependency injection only where it improves testability or architecture.
* Keep controllers thin.
* Put business logic in services.
* Keep database access in the appropriate data/model layer.
* Keep configuration centralized.
* Never commit `.env`.
* Include `.env.example`.
